# CLAUDE.md — ListenUp

SaaS web app that makes spoken conversation **accessible** (speaker-named live captions for deaf/HoH users) and **culturally understandable** (translation that explains slang, register, nuance). Full context: `INTRODUCTION.md`. Build order: `PHASE_0` → `PHASE_5`, one step at a time.

## Stack

- **Frontend:** Next.js 14+ (App Router), TypeScript, Tailwind CSS → Vercel. Real-time via WebSockets.
- **Backend:** FastAPI (Python), native WebSockets → Railway/Render/Fly.io. No Kubernetes.
- **Data/Auth:** Supabase (Postgres, pgvector, Auth, Storage). Redis for translation/slang cache.
- **Ops:** Sentry (errors), PostHog (analytics), GitHub Actions (CI).

## External tools — single responsibility each

| Tool | Job | Rule |
|---|---|---|
| AssemblyAI | Streaming STT + diarization ("who spoke *when*": Speaker 0/1/2) | **Single STT provider.** One service module + mock. No multi-provider abstraction. |
| SpeechBrain ECAPA-TDNN | Speaker ID ("which *real person*": Mom/Dad). 192-dim embeddings → pgvector | Runs locally, CPU only. No per-call cost. |
| Google Translation v3 | General translation (coverage, <200ms, cheap) | Redis-cached. |
| OpenRouter LLM | Enhanced/GenZ translation (register + slang notes, structured output) | Redis-cached. Never blocks live captions. |
| Browser `speechSynthesis` | Text-to-speech, default tier | Free, offline, no key. Male + female for en/ko. Server only *describes* voices; the client renders. |
| ElevenLabs | Premium TTS + consent-gated voice cloning | Opt-in via `TTS_SERVICE=elevenlabs`. Redis-cached audio. Chosen for Korean quality + a verified-consent cloning API. |

AssemblyAI and ECAPA-TDNN run **together**, not as competitors.

## Architecture rules (INTRODUCTION §5)

1. One STT tool, wrapped in one service module with a clean interface + mock.
2. Speaker ID runs locally on CPU — no GPU at MVP.
3. Translation routing: Google = general; OpenRouter = enhanced/slang.
4. Progressive enhancement: show fast Google MT instantly → async LLM slang upgrade. Never block the live caption on the LLM.
5. Audio chunking: 100–250ms chunks over WebSocket. Do not buffer long.
6. Latency budget: mic → caption on screen < ~1s end-to-end.
7. Never force a wrong name: below match confidence → keep the generic label.
8. Speaker cap 4–5 — enforce in code and in UI copy.

## Non-negotiable constraints (INTRODUCTION §6)

- **WCAG 2.1 AA** — keyboard nav, ARIA/screen-reader support, high-contrast mode, adjustable caption font size. A11y failures are build-breaking bugs.
- **Biometric privacy (BIPA / GDPR / Quebec Law 25)** — voice profiles are biometric data. Explicit consent from the **enrolled person** (not just the account holder) + deletion + export, built in the same phase as enrollment (Phase 3).
- **Privacy defaults** — no audio stored by default; transcripts opt-in; encryption at rest; clear retention policy.
- **Cost awareness** — every external API has a mock/stub path; develop and test without burning credits.

## Design system (DESIGN_SYSTEM.md) — STRICT

- **Every UI change must follow `DESIGN_SYSTEM.md`** — Sense-inspired glassmorphism (peach→lilac gradient, frosted glass cards, coral orb, Poppins display + Inter body). The look is pinned: match it, don't reinvent. Use the `frontend-design` skill (plus UI-UX pro / Impeccable if available) for any significant UI work.
- Tokens live in `frontend/app/globals.css` (CSS vars + Tailwind v4 `@theme inline`). Primitives in `frontend/components/ui/` (GlassCard, Orb, Pill, Button, IconButton, ImageTile). Never hardcode colors — use tokens (`text-ink`, `text-ink-soft`, `--accent`, speaker tints, `-strong` state colors for text).
- Coral accent is spent sparingly: orb, primary buttons, active nav icon, play/send. Everything else stays quiet glass.
- A11y overrides are build-breaking (§7): AA contrast on all text-on-glass (darken the glass, not lighten the text; state text uses `--*-strong`), `[data-contrast="high"]` must be styled for every new surface, captions scale via `--caption-scale` only, visible coral focus rings, `prefers-reduced-motion` respected, speaker tints always paired with name labels.
- Gotcha: write only the standard `backdrop-filter` — hand-adding `-webkit-backdrop-filter` makes Lightning CSS drop the standard property (see DEBUG_LOG 1.5.2). After moving routes, `rm -rf frontend/.next` before typechecking.

## Conventions (INTRODUCTION §7)

1. One phase at a time; one step at a time within a phase.
2. Every step: run it → check the step's Verification Gate → fix → continue. No advancing on a red gate.
3. Error protocol (INTRODUCTION §8): static checks → runtime check → verify gate; read the full trace, state root cause in one sentence, fix, re-run; STOP after 2 failed attempts on the same error. Never mark a step done on a compile-only pass.
4. Tests alongside features, never after. Prefer mocks for external APIs.
5. Small commits after each verified step.
6. Log unexpected errors + resolutions in `DEBUG_LOG.md`.
7. Ask before destructive actions (deleting files, dropping tables, rewriting configs).
8. Report after each step: what was built, how verified, errors + fixes, what's next.

- **2026-08-18** — **Multi-scale embedding windows: built, measured, reverted.** Task 2 of `PLAN_SPEAKER_IDENTITY.md`, implemented to spec — full turn plus 1.5 s and 0.75 s centred views, scored max-over-views, only the full window remembered so a noisy short sample could never enter a gallery and make the wrong person easier to match. 11 tests, three mutations each confirmed to fail (single-scale, head-anchored sub-windows, and scoring that ignores the extra views — *the last of those initially passed, because nothing asserted the scales were used at all*). **The measurement: identical numbers on all 12 scenarios, at +11 ms to +25 ms per final turn.** So it was reverted under the task's own gate, which says in as many words that a change costing latency and buying nothing is a regression. **The reason it cannot work is worth more than the code was.** Every scale is a *subset* of the turn's own audio, and for a fixed turn the full window is always the most informative view — so a max over subsets returns the full window's score essentially always. The short-turn weakness is *too little* audio and sub-windows have strictly less: a 1.0 s turn yields a 0.75 s view, which measures 0.478 against a 0.55 threshold. Multi-scale earns its reputation in NeMo's MSDD by driving **segmentation** — short windows locating boundaries, long ones identifying, fused with learned weights over a whole recording — not by squeezing more out of one already-bounded turn. **Where the evidence points instead:** sub-windows can only help when the full window is *contaminated* by two speakers, so the useful version is contamination detection (embed both halves, distrust the turn when they disagree), which needs a mid-turn-speaker-change scenario the eval does not yet model. `trio-short-churn` remains the open target at 0.167 confusion / 0.67 split / 0.58 naming / 5 churn. 481 backend tests, unchanged.

- **2026-08-17** — **Speaker identity now has a number, and getting one found two bugs — one of them mine, in production.** Task 1 of `PLAN_SPEAKER_IDENTITY.md`. `scripts/eval_speaker_id.py` runs 12 constructed sessions with exact ground truth through the **real** decision path (assign → reconcile → SpeakerMapper → matcher) and scores them on seven metrics, of which the two that matter are **merge count** (two people under one label — must be 0, and is) and **name churn** (David becoming Speaker 1 and back). The metrics are pure and **unit-tested against hand-built cases**, because a wrong metric is worse than none — this repo has already chased a 75% score that was a scorer bug. Labels are matched to speakers by **optimal assignment, not majority vote**: a majority mapping silently flatters a system that split one person in two, and a test pins that difference. **Baseline, real ECAPA, 5 distinct speakers, 3 enrolled:** clean-audio scenarios (solo, pair, trio, five, dominant, late-joiner, and both provider-churn variants) are **0.000 confusion / 0.00 split / 0 merge / 1.00 naming** — the architecture is sound on well-separated full-sentence turns. The value is in the hard rows: **`trio-short-churn` (1 s turns + churning labels) scores 0.167 confusion, 0.67 split, 0.58 naming, 5 churn**, which is the reported bug reproduced on demand and the target Task 2 has to move. **Two bugs found by measuring.** (1) *Production*: the display label keyed on the **provider label**, so when diarization put two people under one label the clustering separated them correctly and the mapper handed both the same number — a correct split thrown away at the display layer, which is the dangerous merge direction arriving by the back door. `pair-shared` went 0.500 confusion / 1 merge → **0.000 / 0** once the display followed the *voice*. Folding still releases an interim's orphaned slot, but never for a voice split off the same label. (2) *Harness*: `say -v Samantha` and `say -v Alex` produced **byte-identical audio** — neither is installed, so both rendered in the system default voice, which also matched an existing human fixture at 0.87. Five of five reported merges were two real speakers wearing five names. The silence guard proves a clip contains speech; it proves nothing about **whose**, so the builder now rejects any voice too close to one already accepted, and rejected four. *Had the harness been skipped, the next step would have been tuning thresholds against a corpus with duplicate speakers.* **481 backend tests** (+30).

- **2026-08-15** — **Speaker identity gains the one thing live diarization structurally cannot have: hindsight.** Enterprise attribution beats live systems for two reasons, and only one is an algorithm. The first is that meeting products mostly *avoid* the problem — per-participant audio channels and known logins mean the speaker is metadata, not inference. The second is real and portable: batch diarization ingests the whole recording, clusters globally, and **re-assigns early segments once later evidence arrives**. Online clustering commits with no lookahead, so the first turn of a voice is judged against almost nothing and the resulting split never gets revisited. That is exactly why one person fragmented. `SessionSpeakers.reconcile()` makes that advantage incremental: after every final turn, ask whether any two voices have accumulated enough evidence to be one person, fold them, and emit `speakerMerge` so the client **relabels captions already on screen** — which regroups and recolours them, because grouping and colour key on identity. Three deliberate constraints. Merging retroactively is held to a **stricter bar than joining** (`threshold + RECONCILE_MARGIN`) because it rewrites what a reader has already read, and unlike the live decision it can afford to wait for evidence. It compares **centroids, not best-pair similarity** — max-cosine fuses two voices on a single flattering pair, while the centroid asks whether the collections are the same person on the whole. And a voice needs **two turns** before it can be merged, since one turn is the weak evidence that produced the split and merging on it just moves the coin flip. The older voice always survives, so a display number the reader has been watching does not move under them. **445 backend tests** (+7), with three mutations confirmed to fail: merge-everything, merge-on-one-turn, and labels left pointing at the absorbed voice. *Two of those three initially passed under mutation and had to be rewritten — the turn-count test had a threshold high enough that the guard never mattered, and the label-remap test reached the survivor through the audio path whether the remap happened or not, twice, until it asserted the mapping itself. Both were passing for reasons unrelated to their names.* Still open and honestly out of reach here: multi-scale embeddings (short windows for boundaries, long ones for discrimination) and VB-HMM resegmentation with a switching penalty are the next real gains, and enrolment remains the cheapest of all — it is what gives the enterprise systems a known anchor.

- **2026-08-15** — **One person was Speaker 1, 2 and 3, because the caption label was never the voice.** Reported as a speaker-ID accuracy problem; it was not one. `label = mapper.label(segment.speaker)` — the displayed speaker *was* the provider's diarization label, mapped positionally, and streaming diarization splits a single voice across labels routinely (after a pause, a gain change, or simply because one speaker gives it no contrast to anchor on). The entire voice-identity stack — ECAPA, matcher, session gallery, the 2026-07-30 per-turn work — sat behind `if not self.matcher.profiles: return`, so a user who had never enrolled got raw labels and nothing else. **Enrolment was the wrong precondition:** knowing *that two turns are the same person* needs no profile, only the ability to compare two voices, which the local embedder does on CPU for free. Enrolment is what turns "the same person" into "Mom", and stays a separate step. `SessionSpeakers` now clusters turns by voice for **every** session, signed in or not, reusing the one embedding already computed per turn. **The rule is three bands, not two**, because "not confidently the same" and "confidently different" are different claims: at or above the match threshold the turn joins that voice (the merge that collapses churn); below `SPLIT_FLOOR` the audio is positive evidence of a *different* person and a label carrying two people is split; in between the label keeps the voice it has, which is where the quiet, off-mic, laughing turn lives — churning on it would recreate the reported bug from the other side. Folding happens as an **alias over the existing label mapper** rather than a second namespace, because interim turns are labelled before there is audio to judge, and two namespaces let one person hold two Speaker slots — which is how my first attempt renumbered everyone and pushed a two-person conversation to "Other". A folded label now **releases its slot**, so the four-speaker cap is spent on people who exist. **Measured before tuning:** mock embedder, real human fixtures — same person across two recordings **0.957**, two different people **0.388**, windows within one recording **0.828**; threshold 0.55 and floor 0.45 sit between those, and real ECAPA separates them far wider (~0.9 vs ~0.09). **438 backend tests** (+15 on real voices), with three mutations each confirmed to fail: never-merge (3 tests), never-split (1), and slots not released (1). *Two of my own errors, both caught by tests I wrote to catch them: the empty-gallery `max()` crash on a voice created before its first turn is judged, and — worse — a merge-only rule that kept **two different people** under one label, which is the dangerous direction and the reason the split band exists.* **Two tests changed rather than passed:** `test_ws_transcribe` asserted the provider's label sequence, which is the design being replaced; they now pin what the transport still owes (every turn labelled, cap respected, ordering intact) and the identity rules moved to `test_session_speakers.py` where the fixtures are real voices. *Harness lesson, and a real cost: running a one-off script outside pytest skipped `conftest.py`, so it hit the **live** AssemblyAI service and burned two sessions. `conftest` is the only thing pinning mocks; a script that imports test helpers does not inherit it.*
