# CLAUDE.md — ListenUp

SaaS web app that makes spoken conversation **accessible** (speaker-named live captions for deaf/HoH users) and **culturally understandable** (translation that explains slang, register, nuance). Full context: `INTRODUCTION.md`. Build order: `PHASE_0` → `PHASE_5`, one step at a time.

## Stack

- **Frontend:** Next.js 14+ (App Router), TypeScript, Tailwind CSS → Vercel. Real-time via WebSockets.
- **Backend:** FastAPI (Python), native WebSockets → Railway/Render/Fly.io. No Kubernetes.
- **Data/Auth:** Supabase (Postgres, pgvector, Auth, Storage). Redis for translation/slang cache.
- **Ops:** Sentry (errors), PostHog (analytics), GitHub Actions (CI).

## External tools — single responsibility each

| Tool | Job | Rule |
|---|---|---|
| AssemblyAI | Streaming STT + diarization ("who spoke *when*": Speaker 0/1/2) | **Single STT provider.** One service module + mock. No multi-provider abstraction. |
| SpeechBrain ECAPA-TDNN | Speaker ID ("which *real person*": Mom/Dad). 192-dim embeddings → pgvector | Runs locally, CPU only. No per-call cost. |
| Google Translation v3 | General translation (coverage, <200ms, cheap) | Redis-cached. |
| OpenRouter LLM | Enhanced/GenZ translation (register + slang notes, structured output) | Redis-cached. Never blocks live captions. |
| Browser `speechSynthesis` | Text-to-speech, default tier | Free, offline, no key. Male + female for en/ko. Server only *describes* voices; the client renders. |
| ElevenLabs | Premium TTS + consent-gated voice cloning | Opt-in via `TTS_SERVICE=elevenlabs`. Redis-cached audio. Chosen for Korean quality + a verified-consent cloning API. |

AssemblyAI and ECAPA-TDNN run **together**, not as competitors.

## Architecture rules (INTRODUCTION §5)

1. One STT tool, wrapped in one service module with a clean interface + mock.
2. Speaker ID runs locally on CPU — no GPU at MVP.
3. Translation routing: Google = general; OpenRouter = enhanced/slang.
4. Progressive enhancement: show fast Google MT instantly → async LLM slang upgrade. Never block the live caption on the LLM.
5. Audio chunking: 100–250ms chunks over WebSocket. Do not buffer long.
6. Latency budget: mic → caption on screen < ~1s end-to-end.
7. Never force a wrong name: below match confidence → keep the generic label.
8. Speaker cap 4–5 — enforce in code and in UI copy.

## Non-negotiable constraints (INTRODUCTION §6)

- **WCAG 2.1 AA** — keyboard nav, ARIA/screen-reader support, high-contrast mode, adjustable caption font size. A11y failures are build-breaking bugs.
- **Biometric privacy (BIPA / GDPR / Quebec Law 25)** — voice profiles are biometric data. Explicit consent from the **enrolled person** (not just the account holder) + deletion + export, built in the same phase as enrollment (Phase 3).
- **Privacy defaults** — no audio stored by default; transcripts opt-in; encryption at rest; clear retention policy.
- **Cost awareness** — every external API has a mock/stub path; develop and test without burning credits.

## Design system (DESIGN_SYSTEM.md) — STRICT

- **Every UI change must follow `DESIGN_SYSTEM.md`** — Sense-inspired glassmorphism (peach→lilac gradient, frosted glass cards, coral orb, Poppins display + Inter body). The look is pinned: match it, don't reinvent. Use the `frontend-design` skill (plus UI-UX pro / Impeccable if available) for any significant UI work.
- Tokens live in `frontend/app/globals.css` (CSS vars + Tailwind v4 `@theme inline`). Primitives in `frontend/components/ui/` (GlassCard, Orb, Pill, Button, IconButton, ImageTile). Never hardcode colors — use tokens (`text-ink`, `text-ink-soft`, `--accent`, speaker tints, `-strong` state colors for text).
- Coral accent is spent sparingly: orb, primary buttons, active nav icon, play/send. Everything else stays quiet glass.
- A11y overrides are build-breaking (§7): AA contrast on all text-on-glass (darken the glass, not lighten the text; state text uses `--*-strong`), `[data-contrast="high"]` must be styled for every new surface, captions scale via `--caption-scale` only, visible coral focus rings, `prefers-reduced-motion` respected, speaker tints always paired with name labels.
- Gotcha: write only the standard `backdrop-filter` — hand-adding `-webkit-backdrop-filter` makes Lightning CSS drop the standard property (see DEBUG_LOG 1.5.2). After moving routes, `rm -rf frontend/.next` before typechecking.

## Conventions (INTRODUCTION §7)

1. One phase at a time; one step at a time within a phase.
2. Every step: run it → check the step's Verification Gate → fix → continue. No advancing on a red gate.
3. Error protocol (INTRODUCTION §8): static checks → runtime check → verify gate; read the full trace, state root cause in one sentence, fix, re-run; STOP after 2 failed attempts on the same error. Never mark a step done on a compile-only pass.
4. Tests alongside features, never after. Prefer mocks for external APIs.
5. Small commits after each verified step.
6. Log unexpected errors + resolutions in `DEBUG_LOG.md`.
7. Ask before destructive actions (deleting files, dropping tables, rewriting configs).
8. Report after each step: what was built, how verified, errors + fixes, what's next.

- **2026-07-30** — **Real-time speaker naming: identify *during* the turn, and never show a stale name while unsure.** Follow-up to the per-turn fix — the wrong name was gone from finished captions but still visible live, because identification only ran when a turn went **final**: the in-progress bubble carried the label's previous identity for the whole turn and then flipped. Interim segments are now matched mid-turn (`_identify_interim`), scoped to a turn key of `(turn_id, start)`, starting once the turn has ~1s of its own voice and re-checked as it grows (bounded: ≥1.0s growth between embeds, ≤4 per turn). Interim only ever *upgrades* a name — a weak match leaves the current one alone, since interims arrive several times a second and flipping to generic and back is worse than waiting; the final segment stays authoritative. Second half of the fix is the **carry rule**, now its own knob (`CARRY_GAP_S`, 0.25s) separate from `CONTIGUOUS_GAP_S`: one governs *which audio may be combined*, the other *which name to show while unsure*. A name is carried into a new turn only when it follows the last one almost instantly (speech split mid-flow); after any real pause the turn starts **unnamed** rather than showing the previous speaker. **Measured the floor before tuning it:** on real ECAPA, at the worst position in an utterance a 1.0s window scores **0.633** for the right person (threshold 0.55, margin 0.536) while 0.6s scores **0.478** and fails — so ~1s of "not yet sure" at a speaker change is physical, not an engineering choice, and lowering the window would manufacture the wrong names being removed. The trade-off it leaves was measured, not guessed: never-carry = 0% wrong / 30% unnamed frames for a continuing speaker; carry = 25% wrong / 5% unnamed **only when a different speaker starts with <0.25s gap** (barge-in). 0.25s was chosen because real speaker changes carry a pause and mid-flow splits do not. **Live-simulation QA (interim frames at 300ms, audio streamed as it arrives): natural pauses 0% wrong frames (unchanged) with time-to-correct 3.0s → 1.2s; zero-gap continuous speech 83.3% → 25% wrong frames.** Turn-level sweep still 0.00% wrong-name rate (99.0% accuracy, the 0.8pt being pauses that now start unnamed by design); real ECAPA on human fixtures still 100%. **134 backend tests** (+3: named mid-turn, no stale name after a pause, interim embedding bounded per turn); ruff green. *Harness lesson worth keeping: two QA runs produced nonsense until fixed — one advanced the session clock without feeding silence (buffer/timeline desync), the other sliced PCM at odd byte offsets (int16 misalignment made same-voice similarity read 0.15 instead of 0.91). Verify the harness before trusting a bad number.*

- **2026-07-30** — **Fixed: enhanced captions named the *previous* speaker when people alternated.** Reported symptom (3 enrolled profiles, speakers switching back and forth) reproduced exactly and traced to one line of design, not a tuning problem: identity was resolved **once per diarization label and frozen** (`done=True`), so `_SpeakerState` made the *label* the identity. Streaming diarization reuses labels and routinely attributes the start of a new speaker's turn to the previous speaker's label; every later turn under that label then returned the cached name **without ever looking at the audio again** (proved: `attempts=1, done=True` after five turns by three different people). The name only corrected itself when diarization happened to issue a fresh label — the "wrong for a while, then right" the report describes. **Fix: identify every final turn from its own audio.** `done` is gone (replaced by `overridden`, so tap-to-correct still wins and is now the *only* sticky name); a match decides its turn outright, **including back to `None`** — keeping a name because it was confident once is the bug. Three further defects surfaced during QA, each fixed by a rule now stated in `turn_audio()`: (1) reaching back for extra audio blended two speakers, so a turn that can stand alone is judged alone; (2) in continuous speech consecutive turns abut, so a gap check alone still let a short turn swallow the previous speaker — audio is now only borrowed across sub-0.75s joins **and only if nobody has been credited with it** (`window_owners`); (3) refusing to judge anything under 2s left every turn in fast back-and-forth unnamed (QA: 0% named), so turns ≥1s are matched but must clear an extra 0.10 margin — weak evidence needs a stronger result, never stitched-on speech. Also `speakerUpdate` now carries `fillOnly`: automatic naming may only fill *unnamed* past bubbles, because a label legitimately covers different people now and the old blanket relabel would rewrite the earlier speaker's lines; manual corrections still overwrite. **Verified with a perfect-discriminator mock (isolates naming logic from embedding quality) across 5 diarization behaviours × noise/quiet-mic/short-turn conditions, 910 turns: wrong-name rate 0.55% → 0.00%, accuracy 92.7% → 99.8%.** **Real ECAPA on the human-voice fixtures (same-voice 0.907 / cross 0.088): 75% → 100%, 6 wrong names → 0**, including the pathological single-label case at 1.5s turns. 131 backend tests (+6, and the new ones were confirmed to fail against the old frozen behaviour rather than passing vacuously); ruff/typecheck/lint/build green.

- **2026-07-30** — **Timbre/tone shaping (4 more dimensions) — and the hard limit that shapes the whole feature.** Researched what "customize the sound" can actually mean before building. **`speechSynthesis` speaks straight to the sound card**: verified against `lib.dom.d.ts` that the entire interface is `speak/cancel/pause/resume/getVoices` + 3 read-only booleans — **no AudioNode, no MediaStream, no output routing**. So Web Audio (EQ/compression/reverb, all present and excellent in the browser) **cannot touch browser-voice output**. That splits shaping in two, and the split is now explicit in code: `DIMENSION_SUPPORT` maps each dimension → the tiers it can affect, and the UI **disables what a tier can't do with the reason stated** rather than shipping sliders that silently do nothing. Shape went 4 → **8 dimensions**: delivery (pitch/rate/volume/pauses, browser+) and a new **Tone** group — **Warmth** (250 Hz low-shelf), **Brightness** (3.2 kHz high-shelf), **Evenness** (DynamicsCompressor, ratio 1:1→12:1 with makeup gain) via a real Web Audio graph on cloud audio, plus **Expressiveness**, which unlocked something already in the codebase: `elevenlabs.py` hardcoded `stability: 0.5`, a genuine timbre control frozen at its default. Now exposed as expressiveness = 1 − stability (describes the audible result, not the vendor's term). **Deliberately not shipped:** pitch/rate for cloud voices (baked in at render), and any tone slider for browser voices — a "warmth" dial that did nothing on the free tier would be the exact dishonesty the 2026-07-29 entry rejected. **Two defects caught by the gates, not by eye:** (1) typecheck caught `clampShape` still listing 4 fields by hand, so new dimensions were unclamped — rewritten to derive from `SHAPE_LIMITS` keys, which makes the class of bug impossible; (2) a new test passed alone but failed in-suite — the TTS cache is a **process-wide singleton**, so the first call was served from another test's entry and never reached the provider; fixed with a uuid phrase (order-independent) rather than by resetting globals. Cache key now includes expressiveness, or the first setting rendered would be replayed for every later one (regression test asserts both). **123 backend tests** (+3), ruff/typecheck/lint/build green; node-verified graph math (bypass at 0, monotonic, makeup gain bounded ≤1.5×, shelves bracket speech formants) and clamping of **both** legacy shapes (v1 2-field, v2 4-field) migrating without wiping preferences.
